Backend Overview  The FirstTap backend is designed as a lightweight, modular, AI-driven service layer that manages lesson execution, AI conversations, voice interactions, learner progress, and future scalability. For the Hackathon MVP, the backend uses **Next.js API Routes**, **Gemini AI**, and **JSON-based lesson configurations**, eliminating the need for a complex server while maintaining a production-ready architecture.  The backend follows a **service-oriented architecture**, where each module has a single responsibility and communicates through well-defined APIs. This allows future migration to dedicated backend frameworks (FastAPI, NestJS, or Express.js) without changing the frontend.  ---  # 2. Backend Architecture  ```                      Frontend (Next.js)                             │          ┌──────────────────┼──────────────────┐          │                  │                  │          ▼                  ▼                  ▼   Voice Controller    Lesson Manager    Practice Manager          │                  │                  │          └──────────────┬───┴──────────────────┘                         ▼                Next.js API Routes                         │          ┌──────────────┼──────────────┐          │              │              │          ▼              ▼              ▼   Gemini AI      Lesson Service   Progress Service          │              │              │          └──────────────┼──────────────┘                         ▼                   JSON Lesson Files  ```  Each service is independent and reusable, ensuring clean separation of business logic and easy future expansion.  ---  # 3. Core Backend Modules  ## Authentication Service (Future Ready)  Responsibilities:  - Guest login for MVP  - Future user authentication  - Profile management  - Multi-device support  Current MVP:  - Anonymous guest session only  - No login required  ---  ## Lesson Service  Responsible for:  - Loading lesson configuration  - Managing lesson sequence  - Tracking lesson progress  - Controlling lesson states  - Returning current lesson information  Input:  - Lesson Name  Output:  - Complete lesson JSON  ---  ## AI Conversation Service  Responsibilities:  - Receive learner questions  - Maintain lesson context  - Send prompts to Gemini AI  - Generate contextual mentor responses  - Return structured AI output  Maintains:  - Current lesson  - Current screen  - Current practice state  - Conversation history  This ensures AI responses remain relevant to the learner's current progress.  ---  ## Voice Service  Responsibilities:  - Speech Recognition  - Speech Synthesis  - Language detection  - Voice state management  Conversation Flow:  Listening  ↓  Thinking  ↓  Speaking  ↓  Listening  The microphone automatically resumes after the mentor finishes speaking.  ---  ## Practice Service  Responsible for:  - Monitoring learner interactions  - Detecting mistakes  - Detecting inactivity  - Providing contextual hints  - Recording practice progress  Practice remains entirely simulated.  No real financial transactions occur.  ---  ## Progress Service  Responsible for:  - Lesson completion  - Practice completion  - Confidence score  - Learning analytics  - Future progress history  ---  # 4. Data Models  ## User  ```  User  -----  userId  name  preferredLanguage  avatarPreference  createdAt  ```  MVP:  Guest user only.  Future:  Registered learner accounts.  ---  ## Lesson  ```  Lesson  --------  lessonId  lessonName  language  category  difficulty  estimatedDuration  status  ```  Example  Google Pay  Tamil  Digital Payments  Beginner  ---  ## Lesson Step  ```  LessonStep  ------------  stepId  title  voice  subtitle  screen  animation  highlightTarget  waitDuration  ```  Every lesson consists of multiple reusable lesson steps stored in JSON.  ---  ## Conversation  ```  Conversation  --------------  conversationId  lessonId  userQuestion  aiResponse  timestamp  ```  Maintains conversational continuity throughout the lesson.  ---  ## Practice Session  ```  PracticeSession  ----------------  sessionId  lessonId  attemptNumber  mistakes  hintsUsed  completionStatus  ```  Tracks learner performance inside the simulated environment.  ---  ## Digital Confidence Assessment  ```  DCA  -----  lessonCompletion  practiceCompletion  mistakeCount  hintCount  questionsAsked  overallScore  ```  Outputs the learner's Digital Confidence Score.  ---  # 5. Lesson Configuration Schema  Lessons are configuration-driven.  Example:  ```  Lesson  │  ├── Metadata  ├── Introduction  ├── Demonstration  ├── Practice  ├── Quiz  ├── DCA  └── Completion  ```  Each demonstration step contains:  - Voice narration  - Subtitle  - Screen  - Animation  - Highlight target  - Delay  - Completion condition  Adding a new lesson requires only a new JSON configuration.  No application logic changes are required.  ---  # 6. API Design  ## POST /api/chat  Purpose  Communicate with Gemini AI.  Input  ```  {    lessonContext,    conversationHistory,    userSpeech  }  ```  Output  ```  {    aiReply,    nextState,    emotion  }  ```  ---  ## GET /api/lesson  Purpose  Load lesson configuration.  Input  ```  lessonId  language  ```  Output  Complete lesson JSON.  ---  ## POST /api/progress  Purpose  Store learner progress.  Input  ```  lessonId  practiceData  confidenceScore  ```  Output  ```  Status  ```  ---  ## POST /api/practice  Purpose  Evaluate learner actions.  Input  ```  Current Screen  Clicked Button  Elapsed Time  ```  Output  ```  Correct  Incorrect  Hint Required  Next Action  ```  ---  # 7. Future Database Schema  The MVP uses JSON configuration files.  Future versions will migrate to PostgreSQL or Supabase.  Planned tables:  - Users  - Lessons  - LessonSteps  - PracticeSessions  - ConversationHistory  - DigitalConfidenceScores  - Certificates  - LearningAnalytics  Relationships  ```  User  │  ├── Lessons  │  ├── Practice Sessions  │  ├── Conversations  │  └── Confidence Scores  ```  This structure supports personalized learning while maintaining normalized and scalable data storage.  ---  # 8. Backend Standards & Scalability  The backend follows clean software engineering principles to ensure long-term maintainability.  Standards:  - Modular API architecture  - Configuration-driven lesson engine  - Stateless API routes  - Reusable business services  - Type-safe TypeScript models  - Environment-based configuration  - Secure API key management  - Separation of presentation and business logic  The architecture is designed to scale beyond the Hackathon MVP, enabling support for multiple regional languages, AI avatars, DigiLocker, WhatsApp, Government Services, Banking, Healthcare, and other digital literacy modules without restructuring the backend. By isolating lesson content from application logic, FirstTap can continuously expand its educational offerings while preserving a stable, maintainable, and production-ready backend architecture.   `
